Distribution guide

Preparing NapariSBT for Windows

This guide is for the person building and sharing the packed application. Give users README.html for installation and startup instructions.

Package for distribution

Pack a Windows environment with conda-pack, with SpatialBiologyToolkit installed normally rather than in editable mode. Add these files at the ZIP's root:

NapariSBT.exe
Start_NapariSBT.bat
start_naparisbt.py
README.html
python.exe
Lib/
Library/
Scripts/

Include these four files from this launcher's dist/ folder: NapariSBT.exe, Start_NapariSBT.bat, start_naparisbt.py, and README.html. The Python helper is required for both backup options; it uses only Python's standard library. No C# source or build tools need to be distributed. Distribute the original packed archive with those four files added, rather than rezipping an environment already initialised on another machine.

README_DISTRIBUTOR.html is for the distributor and does not need to be included in the user ZIP.

The launcher targets Windows with .NET Framework 4.5 or later (including the .NET Framework 4.x runtime shipped with Windows 10/11). It is compiled as a GUI application with an explicit asInvoker manifest. It never requests elevation, installs system components, changes the system PATH, or writes to HKLM. Environment changes apply only to the launched processes. Numba's cache and diagnostic logs stay in the user's Local AppData.

The build is unsigned. Code signing/organisational approval is a separate release step where required by the recipient's Windows policy.

The batch and executable launchers run the environment's activation hooks. The direct command-prompt helper deliberately does not execute batch files: it sets the bundled library/search paths, Python isolation, Numba cache, and available OpenSSL certificate defaults itself. Environments that require additional package-specific activation settings need those settings reviewed and supplied before using the direct route. Test the workflows you intend to distribute with each startup option, especially plugins that depend on activation hooks.

Rebuild

On a Windows development machine with the .NET Framework C# compiler:

.\install\napari_sbt_windows\build_launcher.ps1

This builds dist/NapariSBT.exe and copies the batch file, Python helper, user guide, and distributor guide alongside it. No external NuGet packages, Python freezing, or administrator access are used for the build.

Developer checks

.\install\napari_sbt_windows\test_launcher.ps1 -PythonEnvironment C:\path\to\python-environment

These checks use a real Python interpreter with disposable fixture scripts and small temporary environments. They cover first/subsequent runs, failed setup, path changes, activation, Python isolation, log output and application failures. They also compare the child and parent security tokens. The test runner is an unsigned executable; an organisational execution policy may block it.

The Python helper also has focused tests that do not start Napari or execute a newly compiled binary:

$env:PYTEST_DISABLE_PLUGIN_AUTOLOAD = '1'
python -m pytest install/napari_sbt_windows/tests/test_python_launcher.py -q

Before release, test the finished ZIP under a standard Windows user account on a representative target computer. Check Home, network dataset loading, normalisation, workspace save/reopen, and any required background feature or export jobs. A successful compile does not verify those workflows.

Diagnostic files

The executable launcher writes logs to %LOCALAPPDATA%\NapariSBT\logs. Users can find them with the Open logs folder button in the error window. The batch and command-prompt routes print diagnostics in the command window; the user guide also explains how to save that output.
